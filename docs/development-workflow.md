# 開発フロー

## 目的
本プロジェクトでは、実装AIとレビューAIを分けて運用する。

## 基本フロー
1. 実装AIが `plan.md` を参照して開発を進める
2. 開発が一区切りついたら、PR作成可能な状態に整理する
3. 必要に応じて、機能単位でPR分割案を検討する
4. PR分割がレビュー性・整理性の向上に有効な場合のみ分割する
5. PR分割の最終判断は人間が行う
6. 実装AIがPR本文を作成する
7. 人間が別AIへレビュー依頼を行う
8. レビュー結果を踏まえて修正・再整理する

## PR分割の基準
以下に当てはまる場合のみ、PR分割を検討する。
- 機能ごとに責務が明確に分かれている
- 変更範囲が大きく、レビュー負荷を下げられる
- 依存関係を壊さずに段階的に確認できる
- 分割したほうが説明しやすい

以下の場合は無理に分割しない。
- 分割すると文脈が失われる
- 相互依存が強く、かえってレビューしにくくなる
- 差分が小さい

## PRに含める内容
- 目的
- 背景
- 変更内容
- 影響範囲
- テスト・確認内容
- `plan.md` との差異の有無
- 未解決事項
- レビューで見てほしい観点

## レビューAIへの依頼時に渡す情報
- `plan.md`
- PR本文
- 主要な変更ファイル
- 特に確認してほしい点
- `issue-log.md` の関連記録
